# Linear CLI - Full Command Reference

Use the `linear` CLI (v2.3.0, `schpet/tap/linear`) for managing Linear issues,
projects, documents and initiatives from the terminal.

Generated by walking `linear --help` across all subcommands.

## Global

- `--workspace <slug>` — target a specific workspace (available on every subcommand)
- `-V, --version`, `-h, --help`
- `LINEAR_DEBUG=1` — show full error details including stack traces
- `LINEAR_ISSUE_SORT` — default sort order for issue listing

Top-level aliases: `i`=issue, `t`=team, `u`=user, `p`=project, `pu`=project-update,
`cy`=cycle, `m`=milestone, `init`=initiative, `iu`=initiative-update, `l`=label,
`docs`/`doc`=document, `configure`=config.

## Authentication

| Command | Purpose |
|---------|---------|
| `linear auth login` | Add a workspace credential (`-k, --key <key>`; `--plaintext` stores in the credentials file instead of the system keyring) |
| `linear auth logout [workspace]` | Remove a credential (`-f, --force`) |
| `linear auth list` | List configured workspaces |
| `linear auth default [workspace]` | Set the default workspace |
| `linear auth token` | Print the configured API token |
| `linear auth whoami` | Print info about the authenticated user |
| `linear auth migrate` | Migrate plaintext credentials to the system keyring |

Credentials live in `~/.config/linear/credentials.toml` (plaintext mode) or the
macOS keyring.

## Issues

Two distinct listing commands — the biggest change from v1.x:

| Command | Alias | Purpose |
|---------|-------|---------|
| `linear issue mine` | `list`, `l` | **Your** issues. Defaults to `-s unstarted`, sorted by priority |
| `linear issue query` | `q` | Structured search across issues. Defaults to all states, all assignees |

`mine` has no assignee filters and no `--json`. Anything needing `--assignee`,
`-U/--unassigned`, `-A/--all-assignees`, `--search`, `--all-teams`,
`--include-archived` or JSON output must use `query`.

### `linear issue mine`

| Flag | Purpose |
|------|---------|
| `-s, --state <state>` | `triage`\|`backlog`\|`unstarted`\|`started`\|`completed`\|`canceled`. Repeatable. Default `unstarted` |
| `--all-states` | Show all states |
| `--sort <manual\|priority>` | Default `priority` (also via `LINEAR_ISSUE_SORT`) |
| `--team <team>` | Team other than your default |
| `--project <project>` | UUID, slug ID, or name |
| `--project-label <label>` | Issues from all projects carrying this label |
| `--cycle <cycle>` | Name, number, `active`/`now`, `next`, `previous`, or offset like `+1` |
| `--milestone <milestone>` | UUID, or name when `--project` is set |
| `-l, --label <label>` | Repeatable |
| `--limit <n>` | Default 50, `0` = unlimited |
| `--created-after <date>` / `--updated-after <date>` | ISO 8601 or `YYYY-MM-DD` |
| `-w, --web` / `-a, --app` | Open in browser / Linear.app |
| `--no-pager` | Disable automatic paging |

### `linear issue query`

All of the above except `-w`/`-a`, plus:

| Flag | Purpose |
|------|---------|
| `--search <term>` | Full-text search (disables `--sort`) |
| `--search-comments` | Also search comment bodies (requires `--search`) |
| `--team <team>` | Repeatable here |
| `--all-teams` | Query across all teams |
| `--assignee <username>` | Filter by assignee |
| `-A, --all-assignees` | Default |
| `-U, --unassigned` | Only unassigned |
| `--include-archived` | Include archived issues |
| `-j, --json` | JSON output |

### Create / update

`linear issue create` and `linear issue update [issueId]` share most flags:

`-t, --title`, `-d, --description`, `--description-file <path>` (preferred for
markdown), `-a, --assignee <self|user>`, `-p, --priority <1-4>`, `--estimate`,
`--due-date`, `--parent <team_number>`, `-l, --label` (repeatable), `--team`,
`--project`, `-s, --state`, `--milestone`, `--cycle`.

- create-only: `--start`, `--no-use-default-template`, `--no-interactive`
- update-only: `--unassign`, `--clear-cycle`

Use `--cycle=-1` (equals sign) for negative offsets.

### Attachments & links

| Command | Purpose |
|---------|---------|
| `linear issue attach <issueId> <filepath>` | Sidebar link attachment — images do **not** render inline. `-t, --title`, `-c, --comment <body>`, `--public` |
| `linear issue link <urlOrIssueId> [url]` | Link a URL to an issue. `-t, --title` |

```bash
linear issue link https://github.com/org/repo/pull/123          # issue from branch
linear issue link ENG-123 https://example.com --title "Design doc"
```

For an image that renders inline, use `comment add --attach`, not `attach`.

### Relations

`linear issue relation add|delete <issueId> <relationType> <relatedIssueId>`,
`linear issue relation list [issueId]`.

Relation types: `blocked-by`, `blocks`, `related`, `duplicate`.

```bash
linear issue relation add ENG-123 blocked-by ENG-100
```

## Gotchas

- `--sort` is **no longer required** — it defaults to `priority`. Unavailable with `query --search`.
- `linear issue list` still works, but only as an alias of `mine`. It cannot filter by assignee; reach for `query` instead.
- `--workspace` is the global slug flag everywhere **except** `label list`, where it is a boolean meaning "workspace-level labels only".
- `-y` vs `-f` for skipping confirmations is inconsistent (`issue delete` uses `-y, --confirm`, `document delete` uses `-y, --yes`, `milestone delete` uses `-f, --force`, `team delete` uses `-y, --force`). Check the specific command.
- `issue attach` creates a sidebar link and does **not** render images inline; `issue comment add --attach` does.
- Project `--description` is capped at 255 characters by Linear's API — long-form content goes in `--content`.
- `issue commits` only works in a jj repo, not plain git.
- Prefer `--description-file` / `--body-file` / `--content-file` for markdown; inline flags fight with shell quoting.
